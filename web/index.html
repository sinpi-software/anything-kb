The pipeline

Content in. Structure out. Nothing lost.

Every item runs the same four steps, off the request path, retried until it lands.

01 · Ingest →

Post any text

One authenticated endpoint. Content is queued durably and acknowledged — a slow model never blocks you, and nothing gets dropped.

02 · Filter →

Keep the signal

A relevance prompt you write decides what's worth keeping. Off-topic content is set aside — the graph stays free of noise.

03 · Extract →

Pull the entities

Entities and relationships — constrained to the types you configured — are pulled out and resolved against what's already there.

04 · Merge

Grow the graph

New facts are deduplicated into your graph, each edge carrying provenance back to the source it came from.

Then read it all back through one GraphQL endpoint, scoped to you.

The developer surface

Ask the graph a question.

A generic schema: entity and relationship types are data, so one query shape works for any graph you build. Here's a real request and its real response.

POST /graphql · query
{
  nodes(type: "Organization") {
    name
    edges {
      type
      target { name type }
    }
  }
}
200 OK · application/json
{ "data": { "nodes": [
  { "name": "OpenAI",
    "edges": [{ "type": "CREATED",
      "target": { "name": "GPT-5", "type": "Product" } }] },
  { "name": "Anthropic",
    "edges": [{ "type": "CREATED",
      "target": { "name": "Claude", "type": "Product" } }] }
] } }
POST /content   { "text": "OpenAI, led by Sam Altman, released GPT-5." }

Why it's built this way

A graph you can trust to grow.

/ 01

Relevance, not a firehose

A prompt you control gates every item, so the base fills with what matters and skips the rest — deliberately, with a reason recorded.

/ 02

Your schema, your graph

Declare the entity and relationship types for your domain. Extraction is held to them, so the structure is yours — not a generic guess.

/ 03

It compounds

Every source is resolved and merged into what's already known. The same entity from ten sources stays one node, richer each time.

/ 04

Grounded in the source

Every node and edge links back to the content it came from. Nothing in the graph is unattributable.

/ 05

Isolated by tenant

Every read and write is scoped by an API key. One key, one graph — you never see another tenant's, and they never see yours.

/ 06

One API, any consumer

Push in over REST, read out over GraphQL. Build a newsletter, a monitor, or a research tool on top — the graph is the stable interface.
